# AIAssetStudio — 컨셉 스테이트먼트

## 해결하려는 문제

- **어떤 상황에서**: 게임을 만들다 캐릭터 스프라이트, 아이콘, 배경, BGM 같은 에셋이 새로 필요해질 때.
- **누구에게**: 이 PC에서 여러 인디게임을 혼자 만드는 개발자 본인.
- **얼마나 자주**: 새 캐릭터·적·아이템·스테이지를 추가할 때마다. 개발 중에는 주 단위로 반복된다(추정).
- **지금은 어떻게 해결**:
  - 이미지: 외부 생성 도구(image_gen)로 원본을 뽑고, 게임마다 따로 짠 스크립트로 배경 제거·팔레트·픽셀 규격·프레임을 맞춘다(LAST LIGHT의 `build_*_art.py`). 또는 ComfyUI 워크플로를 열어 노드 값을 직접 바꿔 가며 뽑는다.
  - 음악: 파형 합성 스크립트로 직접 만들거나, 유료 서비스(Lyria, Suno)를 비교하려던 참이다.
  - 한계: 게임이 바뀔 때마다 후처리 스크립트를 새로 짜야 한다. ComfyUI는 게임 에셋용 도구가 아니라 매번 설정을 손봐야 한다. 결과물이 흩어지고, 한 게임 안에서 화풍을 유지하기 어렵다. 보컬 없는 반복 BGM을 만들 로컬 수단이 마땅치 않다.

## 타겟 사용자

이 PC(RTX 4090 Laptop 16GB, RAM 32GB)에서 Unity 등으로 2D 인디게임을 혼자 만드는 개발자 본인. 코드와 스크립트는 다룰 줄 알지만, 게임마다 아트·음악 파이프라인을 새로 짜는 데 시간을 쓰고 싶지 않다. 지금은 LAST LIGHT(2D 픽셀아트 로그라이크)를 만들고 있고, 앞으로 다른 장르·화풍의 게임에도 같은 도구를 쓰고 싶다. 공개 배포는 당장 목표가 아니다.

## 가치 제안 (한 문장)

> 여러 인디게임을 혼자 만드는 내가, 새 에셋이 필요할 때 외부 서비스나 게임별 스크립트 대신 이 PC의 로컬 모델로, 프로젝트마다 정한 화풍과 규격에 맞춰 게임에 바로 넣을 수 있는 이미지와 BGM을 한 곳에서 뽑는다. 게임을 만들던 Claude Code 세션도 같은 기능을 직접 호출할 수 있다.

**요구사항 메모 (2026-09-24 추가):** Claude Code에서 제어할 수 있는 인터페이스(MCP 서버, CLI 또는 API)를 계획에 포함한다.

**주 사용 방식 (2026-09-24 결정):** 생성은 주로 Claude Code에게 MCP로 시키고, 웹 화면은 결과를 보고 고르는 갤러리로 쓴다.

## 성공 지표

- **성공 신호 (6개월 뒤)**: LAST LIGHT와 그다음 게임 모두에서 새 에셋을 이 앱으로 만들어 실제 게임에 넣는다. 게임별 후처리 스크립트를 새로 짜지 않는다.
- **실패 신호 (접는 기준)**: 결국 ComfyUI를 직접 열거나 외부 서비스로 돌아간다. 또는 3개월 동안 실제 게임 에셋에 한 번도 쓰지 않는다.

## 가장 큰 가정 (Riskiest Assumption)

- **유형**: 실현 가능성
- **가정 내용**: 로컬 모델로 게임에 쓸 만한 "보컬 없는 반복 BGM"을 만들 수 있다. YuE2에는 연주곡 모드가 없어 가짜 보컬이 섞이고, 악보 편집과 보컬 분리를 거친 결과가 가장 근접했다(2026-09-24, "Yue2 로컬 실행 가능성" 세션).
- **저렴한 검증 방법**: 같은 음악 브리프(LAST LIGHT 전투 BGM: 보컬 없는 어두운 판타지, 100 BPM, 8마디 반복 구절)로 ACE-Step 1.5 연주곡을 한 곡 만들어 YuE2 결과와 들어보고 비교한다. ComfyUI에 워크플로가 있고, 모델 4개(14.7GB, MIT/Apache 2.0)를 받아야 한다.
- **검증 결과 (2026-09-24)**: ACE-Step 1.5로 4곡(마을 브리프 2곡, 전투 브리프 2곡)을 만들었다. 보컬 성분(HDemucs 에너지 비율)이 0~0.9%로, 같은 마을 브리프의 YuE2 결과(27~36%)와 달리 사실상 없었다. 90초 곡 하나에 약 32~36초 걸렸다. 보컬이 없다는 가정은 통과했고, 게임에 쓸 만한 곡인지는 사용자가 들어보고 판단한다. 스크립트는 `spikes/acestep_bgm_test.py`에 있다.
- **다음 가정**: 참고 이미지(필요하면 LoRA)로 한 프로젝트 안의 여러 에셋 화풍을 일관되게 유지할 수 있다.

## 확인된 기술 전제 (2026-09-24 실측)

- ComfyUI 0.37.0(`<ComfyUI 경로>`, 포트 8188)에 Qwen-Image-2.1과 YuE2가 설치돼 있고, 둘 다 HTTP API(`/prompt`, `/history`, `/view`, `/free`)로 생성해 봤다. 앱은 이 API를 호출하는 클라이언트로 만든다.
- Qwen-Image-2.1: 1024² 이미지가 6스텝 고속 모드(Viggle Turbo)로 약 8~18초, 참고 이미지 편집 가능, 투명 배경(RGBA) PNG 생성 확인. 배경 알파에 1% 안팎 잔여값이 남아 정리가 필요하다.
- YuE2: 보컬 곡 생성 확인(한국어 포함). 73초 곡에 첫 로딩 포함 204초.
- 메모리: 16GB VRAM에 두 모델을 동시에 올릴 수 없고, 32GB RAM도 빠듯하다(프롬프트 교체 시 한 장 190초 걸린 사례). 작업은 한 줄로 세우고, 모델을 바꿀 때 `/free`로 메모리를 비워야 한다.
- 라이선스: Qwen-Image-2.1과 Viggle Turbo는 비상업(연구·평가) 라이선스, YuE2는 개인 창작자 결과물 판매 허용. 개인·무료 게임 용도라 사용자가 수용함.
