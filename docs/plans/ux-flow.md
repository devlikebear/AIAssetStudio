# AIAssetStudio — UX 플로우

주 사용 방식은 "Claude Code에게 시키고, 웹 갤러리에서 고른다"이다. 그래서 UX는 두 면으로 나뉜다. Claude Code가 부르는 **MCP 도구**와, 사람이 보는 **웹 갤러리**다.

## 핵심 사용자 저니

게임 작업 중인 Claude Code 세션(예: LAST LIGHT 폴더)에서 시작한다.

1. "에셋 스튜디오에 LAST LIGHT 프로젝트 만들어줘. 32×32 픽셀아트, 12색, 어두운 판타지 화풍" → Claude가 `create_project` 호출
2. "그 화풍으로 그림자 적 스프라이트 4장 뽑아줘" → `generate_image` → 작업 id → `get_job`으로 완료 대기 → Claude가 후보 미리보기를 직접 보고 요약
3. 사용자가 갤러리에서 4장을 체크무늬 배경 위에 확대해 보고 하나를 고른다(또는 Claude에게 "2번으로"라고 말한다)
4. "고른 거 Assets/_Game/Art/Enemies에 넣어줘" → `export_asset`으로 후처리된 PNG가 복사된다

**예상 소요 시간**: 프로젝트가 있으면 요청부터 후보 확인까지 약 1~2분(4장 × 10~20초 + 첫 모델 로딩).
**목표**: 첫 요청 후 2분 안에 "게임에 바로 넣을 수 있는 후보"를 본다.

BGM도 같은 흐름이다. `generate_bgm`으로 후보 2곡을 받고, 사람은 갤러리에서 반복 재생으로 들어보고 고른다. Claude는 음악을 들을 수 없으므로 BGM 선택은 항상 갤러리에서 한다.

## MCP 도구 (Claude Code가 보는 "화면")

| 도구 | 목적 | 주요 입력 | 돌려주는 것 |
|---|---|---|---|
| `studio_status` | 백엔드·ComfyUI·모델 준비 상태, 대기열 길이 | 없음 | 상태 요약, 빠진 노드·모델 목록 |
| `list_projects` / `get_project` | 프로젝트와 프리셋 조회 | 프로젝트 이름 | 화풍·규격·내보내기 폴더 |
| `create_project` / `update_project` | 프리셋 만들기·고치기 | 이름, 화풍 문구, 픽셀아트 여부, 논리 해상도, 최대 색 수, 참고 이미지 경로(1장), 내보내기 폴더 | 프로젝트 |
| `generate_image` | 스프라이트·아이콘 후보 생성 요청 | 프로젝트, 종류(sprite/icon), 설명, 장 수(기본 4), 시드(선택) | 작업 id (바로 반환) |
| `generate_bgm` | BGM 후보 생성 요청 | 프로젝트, 브리프, BPM, 길이, 반복 여부, 보컬 여부·가사 | 작업 id (바로 반환) |
| `get_job` | 작업 상태 조회, 최대 60초까지 완료 대기 | 작업 id, 대기 초 | 상태·진행 단계. 완료 시 이미지는 작은 미리보기 이미지, 음악은 파일 경로·길이·반복 구간 + 갤러리 링크 |
| `list_assets` | 에셋 목록 | 프로젝트, 종류, 상태(후보/선택/버림) | 에셋 요약 목록 |
| `set_asset_status` | 고르기·버리기 | 에셋 id, 상태 | 갱신된 에셋 |
| `export_asset` | 후처리본을 게임 폴더로 복사 | 에셋 id, 대상 폴더(없으면 프로젝트 내보내기 폴더), 파일 이름(선택) | 복사된 파일 경로 |
| `cancel_job` | 잘못 요청한 작업 취소 | 작업 id | 취소 결과 |

## 갤러리 화면 목록

| 화면명 | 목적 (한 줄) | 주요 요소 | 진입 경로 |
|------|----------|--------------|--------|
| 갤러리 메인 | 프로젝트의 후보를 작업별로 훑어보기 | 프로젝트 선택, 종류·상태 필터, 작업별 후보 묶음, 대기열 패널 | 브라우저에서 `http://127.0.0.1:<port>/`, 또는 `get_job` 결과의 링크 |
| 후보 상세 | 한 후보를 자세히 보고 결정 | 확대 보기(원본/후처리 전환), 생성 기록(프롬프트·시드·모델), 고르기·버리기·내보내기 | 메인에서 후보 클릭 |
| 프로젝트 정보 | 프리셋 확인 (읽기 전용) | 화풍 문구, 규격, 참고 이미지, 내보내기 폴더 | 메인의 프로젝트 이름 클릭 |

프로젝트 만들기·고치기는 MVP에서 MCP로만 한다.

## 화면 간 전이

```
[갤러리 메인]
  ├─ (후보 클릭)          → [후보 상세]
  ├─ (고르기/버리기 버튼) → [갤러리 메인 / 카드 상태만 바뀜]
  ├─ (프로젝트 이름 클릭) → [프로젝트 정보]
  └─ (대기열 항목 클릭)   → [갤러리 메인 / 해당 작업 묶음으로 스크롤]

[후보 상세]
  ├─ (고르기/버리기/내보내기) → [후보 상세 / 상태 갱신, 내보낸 경로 표시]
  ├─ (이전/다음)              → [같은 작업의 다른 후보]
  └─ (닫기)                   → [갤러리 메인]
```

## 화면별 주요 상태

### 갤러리 메인
- **Happy path**: 작업별 후보 묶음. 이미지는 체크무늬 배경 위에 정수배 확대, 음악은 반복 재생 토글이 있는 플레이어.
- **Empty state**: 프로젝트가 없으면 "Claude Code에서 '에셋 스튜디오에 프로젝트 만들어줘'라고 요청하세요"와 MCP 등록 명령을 보여준다. 프로젝트는 있는데 에셋이 없으면 예시 요청 문장 2~3개를 보여준다.
- **Error state**: 백엔드나 ComfyUI에 연결할 수 없으면 상단 배너로 원인(ComfyUI 꺼짐, 모델 없음 등)과 다시 시도 버튼을 보여준다.
- **진행 중 상태**: 대기 중·생성 중·후처리 중인 작업은 자리 표시 카드로 보이고, 끝나면 후보로 바뀐다.

### 후보 상세
- **Happy path**: 확대 보기와 생성 기록, 결정 버튼.
- **Empty state**: 해당 없음 (후보가 있어야 진입).
- **Error state**: 파일이 지워졌거나 읽을 수 없으면 기록만 보여주고 "재생성" 대신 "같은 설정 복사"(MCP 요청 문장)를 안내한다.

### 대기열 패널
- **Happy path**: 현재 작업의 종류·단계·경과 시간, 대기 중인 작업 목록.
- **Empty state**: "대기 중인 작업 없음".
- **Error state**: 실패한 작업은 오류 메시지와 함께 남기고, 다시 요청할 수 있는 MCP 문장을 보여준다.

## 결정적 엣지케이스

1. **ComfyUI가 꺼져 있거나 필요한 노드·모델이 없음**
   - 상황: PC 재시작 후, 또는 ComfyUI 업데이트로 노드 이름이 바뀜.
   - 대응: 백엔드가 설정된 경로로 ComfyUI를 띄우고 최대 120초 기다린다. 시작할 때 필요한 노드·모델 목록을 점검해서, 빠진 것을 `studio_status`와 갤러리 배너에 이름으로 보여준다.
2. **메모리 압박으로 작업이 멈춤**
   - 상황: 텍스트 인코더를 다시 불러오다 RAM이 바닥나 한 장에 190초가 걸린 사례가 있다. 다른 프로그램이 GPU를 쓰면 더 심해진다.
   - 대응: 종류별 작업 제한 시간(이미지 5분, 음악 10분)을 두고, 넘으면 실패로 기록한다. 단계별 소요 시간을 남긴다. `studio_status`에 현재 VRAM·RAM 여유를 보여준다.
3. **여러 Claude Code 세션이 동시에 요청**
   - 상황: 게임 프로젝트 두 곳에서 동시에 생성 요청.
   - 대응: 모든 요청은 백엔드의 단일 대기열로 들어가 순서대로 처리된다. 같은 모델 작업끼리는 묶어서 처리해 모델 교체를 줄인다.
4. **내보내기 폴더에 같은 이름의 파일이 있음**
   - 상황: 같은 에셋을 두 번 내보내거나 이름이 겹침.
   - 대응: 덮어쓰지 않고 번호를 붙여 저장한 뒤 실제 경로를 돌려준다.
5. **생성이 끝난 뒤에도 ComfyUI가 메모리를 잡고 있음**
   - 상황: 다른 GPU 작업(LoRA 학습 등)이 느려진다.
   - 대응: 대기열이 비고 60초가 지나면 ComfyUI 메모리를 비운다(`/free`). 이미지↔음악 모델을 바꿀 때도 비운다.
