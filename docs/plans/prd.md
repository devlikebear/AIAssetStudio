# AIAssetStudio — PRD (MVP)

## Overview

여러 인디게임을 혼자 만드는 개발자(본인)를 위한 로컬 게임 에셋 스튜디오. 이 PC의 로컬 모델(이미지는 Qwen-Image-2.1, 연주곡은 ACE-Step 1.5, 보컬 곡은 YuE2)로 프로젝트마다 정한 화풍과 규격에 맞는 스프라이트, 아이콘, BGM을 만든다. 생성은 주로 Claude Code가 MCP로 요청하고, 사람은 웹 갤러리에서 결과를 보고 고른다. 모든 생성은 백엔드 하나가 대기열로 순서대로 처리해서, 16GB VRAM·32GB RAM에서 작업끼리 메모리를 뺏지 않게 한다.

## 구조 원칙

- **백엔드 하나가 GPU 작업을 전담한다.** ComfyUI 호출, 작업 대기열, 후처리, 프로젝트·에셋 저장을 모두 맡고 HTTP API를 연다.
- **MCP 서버와 웹 갤러리는 이 API만 부른다.** ComfyUI나 GPU를 직접 건드리지 않는다.
- **생성은 비동기다.** 요청하면 작업 id를 바로 돌려주고, 결과는 작업 조회로 받는다. 이미지 한 장은 10~20초, BGM 한 곡은 수 분까지 걸린다.

## MVP 기능 목록

| # | 기능명 | 한 줄 설명 | MVP에 필요한 이유 |
|---|-----|---------|--------------|
| 1 | 프로젝트 프리셋 | 게임마다 화풍 문구, 참고 이미지, 픽셀 규격, 내보내기 폴더를 저장 | 없으면 "프로젝트마다 같은 화풍·규격"이라는 핵심 가치가 성립하지 않음 |
| 2 | 이미지 에셋 생성 | 스프라이트·아이콘을 투명 배경 후보 여러 장으로 만들고 게임 규격으로 후처리 | 앱의 주 산출물. 후처리가 없으면 게임에 바로 못 넣음 |
| 3 | BGM 생성 | 분위기·악기·BPM·길이로 반복 재생용 곡을 만듦. 연주곡이 기본, 보컬 곡은 선택 | 두 번째 산출물. 유료 음악 서비스를 대체하려는 목적 |
| 4 | MCP 서버 | Claude Code가 프로젝트 조회, 생성 요청, 결과 확인, 내보내기를 도구로 호출 | 주 사용 방식이 "Claude Code에게 시키기"라서 이게 기본 조작 수단 |
| 5 | 웹 갤러리 | 작업별 후보를 보고 고르거나 버리고, 대기열 상태를 확인 | 최종 선택은 사람이 해야 함. Claude가 뽑은 결과를 검토할 곳 |

## 유저 스토리 & 수용 기준

### 기능 1: 프로젝트 프리셋

**유저 스토리**
> As a 여러 게임을 혼자 만드는 개발자, I want to 게임마다 화풍과 규격을 한 번 정해 두고 싶다, so that 매번 설정하지 않아도 같은 게임의 에셋이 같은 화풍과 규격으로 나온다.

**수용 기준**
- Given 새 프로젝트를 만들 때, When 이름·화풍 문구·참고 이미지(MVP는 0~1장)·픽셀아트 여부·논리 해상도(예: 32×32)·최대 색 수·내보내기 폴더를 지정하면, Then 프로젝트 설정으로 저장되고 MCP와 웹 갤러리 양쪽에서 조회된다.
- Given 픽셀아트 프로젝트(32×32, 12색), When 스프라이트를 생성하면, Then 결과 PNG는 32×32 논리 해상도에 12색 이하이고 투명 배경이다.
- Given 참고 이미지가 등록된 프로젝트, When 이미지를 생성하면, Then 참고 이미지가 생성 입력에 들어가고 에셋 기록에 남는다.

### 기능 2: 이미지 에셋 생성

**유저 스토리**
> As a 게임에 넣을 에셋이 필요한 개발자, I want to 에셋 종류와 설명만 주고 투명 배경 후보 여러 장을 받고 싶다, so that 마음에 드는 것을 골라 손질 없이 게임에 넣을 수 있다.

**수용 기준**
- Given ComfyUI가 실행 중, When 스프라이트 4장을 요청하면, Then 4장의 RGBA PNG 후보가 생성되고 배경 알파는 0으로 정리된다.
- Given 픽셀아트 프로젝트, When 후처리가 끝나면, Then 논리 해상도 원본과 미리보기용 정수배 확대본이 함께 저장되고, 부분 알파 픽셀이 없다.
  - 구현 출발점: LAST LIGHT의 아트 처리 파이프라인(최근접 축소 → 고정 팔레트 매핑 → 이진 알파). 다만 생성 이미지의 픽셀 격자가 균일하지 않아서, 단순 최근접 축소로는 뭉개질 수 있다. 격자 크기를 추정하는 단계가 필요한지 초기 페이즈에서 확인한다.
- Given 생성이 끝난 후보, Then 프롬프트·시드·모델·워크플로·후처리 설정이 기록되어 같은 결과를 다시 만들 수 있다.
- Given 아이콘 종류, When 생성하면, Then 정사각형에 여백을 둔 투명 배경 아이콘으로 나온다.

### 기능 3: BGM 생성

**유저 스토리**
> As a 스테이지 음악이 필요한 개발자, I want to 분위기·악기·BPM·길이를 적으면 보컬 없는 반복용 BGM 후보를 받고 싶다, so that 유료 서비스 없이 게임 음악을 채울 수 있다.

**수용 기준**
- Given 연주곡(기본) 옵션, When 90초 BGM을 요청하면, Then ACE-Step 1.5로 생성되어 OGG와 WAV 파일이 생기고, 들었을 때 가사나 노랫소리가 없다.
  - 근거(2026-09-24 테스트): ACE-Step 4곡의 보컬 성분(HDemucs 에너지 비율)은 0~0.9%로, 같은 브리프의 YuE2 결과(27~36%)와 달리 사실상 없었다. 90초 곡 하나에 약 32~36초 걸렸다.
  - 생성 요령: 가사 칸에 `[Instrumental]` 또는 `[Main Theme - 악기]`처럼 인트로·아웃트로 없는 구간 태그를 넣는다. 구간 태그를 쓴 곡은 첫 소절부터 제 음량으로 시작했다.
- Given 반복 옵션, When 생성이 끝나면, Then 끝부분 무음을 잘라낸 뒤 BPM으로 계산한 마디 경계에서 반복 구간을 자르고, 이음새를 20~50ms 크로스페이드해서 반복 재생할 때 딸깍 소리가 나지 않는다. 테스트한 4곡 모두 요청한 90초보다 일찍 끝나서 마지막 3~6초 이상이 무음이었다. 음악적으로 자연스럽게 이어지는지는 보장하지 않으며, 후보를 들어보고 고른다.
- Given 보컬 옵션과 가사, When 요청하면, Then 보컬 곡이 생성된다(YuE2).
- Given 음악 작업이 끝나면, Then 다음 작업 전에 음악 모델이 메모리에서 내려간다.

### 기능 4: MCP 서버 (Claude Code 연동)

**유저 스토리**
> As a Claude Code로 게임을 만드는 개발자, I want to 게임 작업 중인 세션에서 "이 프로젝트 화풍으로 X를 뽑아서 Y 폴더에 넣어줘"라고 시키고 싶다, so that 작업 흐름을 끊지 않고 에셋을 채울 수 있다.

**수용 기준**
- Given MCP 서버가 사용자 범위로 등록됨, When 다른 프로젝트의 Claude Code 세션에서 이미지 생성 도구를 부르면, Then 작업 id가 바로 돌아오고, 작업 조회 도구로 완료 후 후보 이미지를 Claude가 직접 볼 수 있다.
- When 내보내기 도구를 에셋과 경로로 부르면, Then 후처리된 파일이 그 경로(또는 프로젝트의 내보내기 폴더)에 복사된다.
- Given 작업이 진행 중, When 새 요청이 들어오면, Then 대기열에 들어가 순서대로 처리되고 GPU 작업이 동시에 돌지 않는다.
- Given ComfyUI가 꺼져 있음, When 생성 도구를 부르면, Then 원인을 알려주는 오류가 돌아온다(또는 백엔드가 ComfyUI를 띄운다).

### 기능 5: 웹 갤러리

**유저 스토리**
> As a 최종 선택을 내리는 개발자, I want to 브라우저에서 후보를 한눈에 보고 고르거나 버리고 싶다, so that Claude가 뽑은 결과 중 게임에 넣을 것을 내가 정할 수 있다.

**수용 기준**
- Given 프로젝트에 후보가 있음, When 갤러리를 열면, Then 작업별로 묶여 보이고, 이미지는 체크무늬 배경 위에 실제 크기와 확대본으로, 오디오는 반복 재생으로 들을 수 있다.
- When 후보를 고르거나 버리면, Then 상태가 저장되고 MCP의 에셋 목록에도 바로 반영된다.
- Then 진행 중인 작업과 대기열이 보인다.

## Out of Scope (MVP에서 명시적으로 뺀 것)

- **4방향 시트와 애니메이션 프레임(걷기 등)** — 뺀 이유: 이미지 모델로 프레임끼리 모양을 맞추기 어려워 별도 검증이 필요. 재검토 시점: MVP 이후 첫 확장 후보
- **타일셋, 배경, 초상화** — 뺀 이유: 추가는 쉽지만 MVP를 키움. 재검토 시점: v1.1
- **효과음** — 뺀 이유: 설치된 모델로 만들 수 없음. 재검토 시점: 효과음 모델 검토 후
- **CLI** — 뺀 이유: Claude Code 연동은 MCP로 충분. 같은 API를 감싸면 되므로 나중에 쉽게 추가. 재검토 시점: 스크립트 자동화가 필요해질 때
- **웹에서 직접 생성하는 전체 UI** — 뺀 이유: 주 사용 방식이 Claude Code. 갤러리는 검토·선택만. 재검토 시점: 사용해 보고 불편하면
- **LoRA 학습 UI** — 뺀 이유: ai-toolkit으로 따로 가능하고 MVP 가치와 무관. 학습된 LoRA를 프로젝트 설정에 연결하는 것은 v1.x 후보
- **엔진별 임포트 자동화(Unity 임포트 설정, .meta 등)** — 뺀 이유: 게임마다 다름. MVP는 폴더로 내보내기까지
- **공개 배포(설치 안내, 모델 다운로드 관리, 사양별 대응)** — 뺀 이유: 본인 전용으로 결정
- **악보(ABC) 편집 UI, 이미지 부분 편집(인페인팅)** — 뺀 이유: MVP 핵심 흐름 밖

## 의존성

- **외부 API**: 없음. 모든 생성은 로컬.
- **로컬 서비스**: ComfyUI 0.37.0(`<ComfyUI 경로>`, 127.0.0.1:8188). 노드 이름과 API 그래프가 이 버전에 맞춰져 있으므로 업데이트는 테스트 후에 한다.
- **모델**: Qwen-Image-2.1 int8 본체·텍스트 인코더·VAE, Viggle Turbo LoRA, YuE2 int8, ACE-Step 1.5 turbo(본체·텍스트 인코더 2개·VAE, 2026-09-24 설치, MIT).
- **도구**: ffmpeg(OGG 인코딩), Claude Code(MCP 사용자 범위 등록).
- **인증/권한**: 없음. 로컬 전용.
- **플랫폼**: Windows 11, 이 PC(RTX 4090 Laptop 16GB, RAM 32GB).

## 비기능 요구사항

- **성능**: 이미지 후보 한 장 10~20초(고속 6스텝 기준), BGM 90초 곡은 수 분 이내. MCP 호출은 생성 완료를 기다리지 않고 바로 응답한다.
- **자원**: GPU 작업은 한 번에 하나만 돈다. 같은 모델 작업끼리 묶고, 이미지↔음악 모델을 바꿀 때와 음악 작업 후에 ComfyUI 메모리를 비운다(`/free`).
- **호환성**: Windows 11 전용.
- **데이터 보존**: 생성 원본, 후처리본, 생성 기록(프롬프트·시드·모델·설정)을 로컬에 모두 남긴다. 버린 후보도 바로 지우지 않는다.
- **접근성**: 해당 없음.
- **보안/개인정보**: 백엔드는 127.0.0.1에만 연다.

## 미결 사항

- **BGM 엔진**: 연주곡은 ACE-Step 1.5, 보컬 곡은 YuE2로 나눈다(2026-09-24 테스트 기준). 음악 품질은 사용자 청취로 최종 확인한다.
- **기술 스택**: 스펙 단계 끝에서 확정.

## 검증 필요 (따로따로만 확인했거나 아직 안 해 본 것)

- **참고 이미지 + 투명 배경**: 투명 배경은 참고 이미지 없는 생성에서만, 참고 이미지는 불투명 이미지 편집에서만 확인했다. 두 가지를 함께 쓸 때 결과가 투명하게 나오는지는 한 장 생성해 봐야 안다. 텍스트 인코더 노드가 참고 이미지의 알파를 흰 배경으로 합쳐서 보기 때문에 결과가 달라질 수 있다.
- **참고 이미지 여러 장의 VRAM**: 1장일 때 피크 약 15GB였다. 2장 이상은 16GB에서 확인하지 않았다. 부족하면 `Qwen Image 2.1 Cache` 노드를 `device=cpu`로 둔다.
- **픽셀 격자 정리**: 위 기능 2의 구현 출발점 참고.
- **BGM 음악 품질과 반복 구간**: 보컬이 없다는 것은 측정으로 확인했다. 게임에 쓸 만한 곡인지, 반복 구간이 자연스럽게 이어지는지는 들어봐야 안다.
